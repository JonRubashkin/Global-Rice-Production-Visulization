# Global Rice Production Visualization

An interactive, single-page D3.js (v7) choropleth of **global rice (paddy)
production by country, 1961–2024**. Shade the world map by production
(tonnes), harvested land (hectares), or yield (t/ha); scrub or animate
through years; and hover any country for population, area, production, and
yield.

![metric toggle + year slider + Natural Earth choropleth]

## Features

- **Natural Earth choropleth** (`d3.geoNaturalEarth1`) rendered once, with
  fills updated via a D3 data-join — the SVG is never redrawn on year change.
- **Year slider** (1961–2024) with a prominent year readout and **play/pause**
  animation. Slider input is debounced (requestAnimationFrame) so dragging
  stays smooth.
- **Three metrics** — Production, Harvested land, Yield — as mutually
  exclusive toggle buttons. Production and area use a **log color scale**
  (values are heavily skewed by China & India); yield uses a linear scale.
  All use a sequential `interpolateYlGn` ramp.
- **Tooltip** showing country, population, area harvested, production, and
  yield — formatted with thousands separators (yield to 2 decimals). It
  follows the cursor, clamps to the viewport, and clears on mouse-out.
- **Click-to-pin** tooltip and a **searchable country list** so small
  countries are easy to inspect; search also zooms to the country.
- **Zoom/pan** with +, −, and reset controls.
- **No-data handling**: countries with no rice figure for the selected year
  are shaded light gray and report "No data" in the tooltip.
- Smooth ~300 ms fill transitions on year/metric change; responsive down to
  ~1024 px.

## Project layout

```
data/                     # source CSVs (inputs to preprocessing)
  rice-production.csv      #   Entity, Code, Year, Rice - Production (tonnes)
  rice-yields.csv          #   Entity, Code, Year, Rice - Yield (t/ha)
  population.csv           #   Entity, Code, Year, Population
scripts/
  preprocess.mjs           # CSV -> compact JSON + ISO-augmented TopoJSON
  serve.mjs                # zero-dependency static server for ./public
  world-countries.json     # ISO numeric <-> alpha-3 reference table
public/                   # the deployable app (static files)
  index.html, styles.css, app.js
  rice-data.json           # generated by preprocess (keyed by ISO3 + year)
  world-110m.json          # world-atlas TopoJSON, augmented with iso_a3
  vendor/                  # d3.min.js, topojson-client.min.js (vendored)
```

## Data

The CSVs are FAOSTAT rice (paddy) figures distributed via **Our World in
Data**, plus an OWID/UN population series. Crucially, every country row
already carries an **ISO 3166-1 alpha-3 code** in its `Code` column, so the
preprocessing join is by code, not by name. The OWID export ships **yield**
rather than area harvested, so **area is derived as `production ÷ yield`**
(guarding against divide-by-zero) during preprocessing.

### Preprocessing (`npm run preprocess`)

`scripts/preprocess.mjs` (Node, no dependencies):

1. Parses the three CSVs.
2. Drops FAO regional aggregates (rows with an empty `Code`) and **logs every
   one** rather than silently dropping it.
3. Builds the per-country/per-year record `{ production, area, yield,
   population }`, computing area from production and yield. The population
   series ends in **2023** while rice data runs to **2024**, so for years with
   no population figure the tooltip falls back to the most recent available
   year and labels it (e.g. "Population (2023)") rather than showing a blank.
4. Augments `public/world-110m.json` so each map polygon gets an `iso_a3`
   property — resolved from the TopoJSON's numeric ISO id via
   `world-countries.json`, with an explicit name→ISO override table for the
   tricky cases ("Viet Nam", "Türkiye", "W. Sahara", "Dem. Rep. Congo", …).
   Any unresolved polygon is **logged**.
5. Writes `public/rice-data.json` (`{ meta, countries }`, where `meta`
   carries the year range and per-metric global value extents used to build
   the color scales).

Historical entities that the modern map has no polygon for (USSR, Yugoslavia,
"Sudan (former)") use OWID pseudo-codes (`OWID_USS`, …); their data is kept
and logged — they simply don't render on a present-day map. The split cases
(Sudan → Sudan + South Sudan) appear under their own ISO codes for the years
they exist.

## Running it

Requirements: **Node 18+** (only used for preprocessing and the static
server; the app itself is plain HTML/CSS/JS with D3 vendored locally — no
build step, no CDN needed at runtime).

```bash
# 1. regenerate the JSON data + augmented map (optional — outputs are committed)
npm run preprocess

# 2. serve ./public and open the printed URL
npm run serve            # -> http://localhost:8080/
# or:  npm start         # preprocess, then serve
```

Any static server works just as well, e.g. `python3 -m http.server -d public
8080`. Opening `public/index.html` directly via `file://` will not work
because the app fetches JSON (browsers block `file://` fetches) — serve it
over HTTP.

## Testing

The app was verified end-to-end in a headless DOM harness: the page loads
with **no console errors or warnings**, ~177 country polygons render, fills
and the legend update across all three metrics, and the slider was swept
across the full 1961–2024 range with no thrown errors or `NaN` fills.
Tooltip values were checked against the source CSVs — e.g. India 2020
(182,702,930 t; 4.06 t/ha; 45,007,373 ha; pop 1,402,617,694) and China 1990
(189,331,000 t; 5.73 t/ha; 33,064,562 ha; pop 1,153,582,725).
